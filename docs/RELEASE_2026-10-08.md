## Build fixes and validation

- The Dockerfile accepts an optional BuildKit `build_ca` secret for npm TLS
  verification. Certificates are not copied into the runtime image.
- Next.js was patched from 15.5.25 to 15.5.27; the lockfile updates sharp to
  0.35.5 and source-map-js to 1.2.2. The dependency audit reported zero
  vulnerabilities after these updates.
- All 226 frontend tests and the production build passed locally in Docker
  and again in the final build on the Finspot host.
- The local container returned HTTP 200 for `/healthz`, `/`, and `/signin`.
- The UAT frontend rollout completed successfully. Public HTTPS requests to
  `/healthz`, `/`, and `/signin` each returned HTTP 200 after rollout.
- Local Docker image uploads failed through the Docker proxy. The same
  frontend source was transferred without environment files or local build
  output and built on the Finspot host, then successfully pushed to Harbor.

To build locally behind the corporate certificate authority:

```sh
docker build --platform linux/amd64 \
  --secret id=build_ca,src=/path/to/trusted-ca-bundle.pem \
  -t <release-image> ./frontend
```

The CA bundle must be nonempty. macOS keychain reads inside a restricted
sandbox can return an empty bundle, so verify the export before building.
Keep TLS certificate verification enabled.

`vediyappanm05/finspot-prod-devops`, path `apps/argus-tradeops-uat`.

sync policy. This release therefore updates only the live frontend image.

sync; otherwise that sync may restore an older image. The application
repository `rajkumar-madhu/argus-tradops-fonspot-final-codex` is accessible,
but is not the current Argo source.

If rollback is necessary while that GitOps source remains unavailable,
restore only the frontend image to the previous digest above. Do not apply
the local `deploy/uat` overlay: it targets a different namespace and stack.
