## Keycloak CORS repair

The user's browser reported a token endpoint response of 200 that was unreadable
because its Access-Control-Allow-Origin header was missing. The Argus realm's
`tradeops` client allowed the UAT callback in redirectUris, but webOrigins had
only local development addresses. Added exactly
`https://tradeops-uat.finspot.in` to webOrigins using the authenticated admin API.
Existing origins, redirect URIs, public-client mode, and enabled flows remain.
The API returns origins in a different order; their order has no CORS meaning.
No application rebuild or rollout was needed.

Verified externally with a deliberately invalid authorization code: before the
repair, the token endpoint returned 400 without Access-Control-Allow-Origin;
afterward, it returned the UAT origin and Access-Control-Allow-Credentials.
An unrelated origin received no Access-Control-Allow-Origin. This verifies the
reported CORS defect, not a completed credentialed browser login. Browser login
automation remains blocked by a saved user permission preference. Restart login
from `/signin` because the previous authorization code may already be consumed.
The exact pre-change origins are backed up in
`/private/tmp/argus-keycloak-cors-backup-20261007.json` without credentials.
